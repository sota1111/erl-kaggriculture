## 1. スコアの正体 — レーティングであり、エピソード単位で動く

### 1.1 所持金ではない

ゲームの `reward` はシーズン終了時の所持金(ローカルでは 10万台)。
**リーダーボードのスコアはレーティングで、新規提出は 600.0 から始まる。**

### 1.2 時間ではなくエピソードが単位

**レーティングは1エピソードごとに動き、ラダーがエピソードを供給する速度はエージェントによって
10倍違う。**「2日待つ」は、あるエージェントには 17 エピソード、別のエージェントには 170
エピソードを意味する。したがって:

> **収束の判定は経過時間ではなく (スコア, 消化エピソード数) の組で行う。**
> エピソードあたりのドリフトが小さくなり、**その符号が最低1回反転**したら読んでよい。

本リポジトリの実測(`results/baseline/rating_convergence.md`、`tools/rating_probe.py`):
供給レートは約4分に1本。28エピソードまでの推移は 600.0 → 967.0 → 869.7 → 920.6 で、
**±60 程度の振幅で振動している。**

### 1.3 「収束」は存在しない

レーティングは**動き続けるフィールドに対する相対値**である。1バイトも変えていない
エージェントが 135 エピソードで 182 ポイント下がった例が公開されている
([destbreso, Rating convergence](https://www.kaggle.com/code/destbreso/rating-convergence-episodes-not-hours))。
**「収束値」を固定値として扱ってはならない。読める瞬間があるだけである。**

また **LB はチームの最高スコアではなく、現在対戦中の提出を表示する。**
5回/日 出せるが、実際に対戦に回るのは直近のものだけなので、
**弱い個体を上書きで出すと、良い個体は対戦から降りる。**

## 3. ゲーム仕様

完全なルールは **`docs/env/RULES.md`**、機械可読な設定は **`docs/env/kaggriculture.json`**
(`kaggle-environments` 1.32.7 由来、Apache-2.0)。

**アリーナの設定はローカル既定値と完全に一致する**——実際のリプレイ JSON から抽出して
全項目を照合済み(env version `0.1.0`、`episodeSteps` 720、`actTimeout` 1、
`startingMoney` 3000、`marketParams` 空、`turnsPerDay` 24 ほか全一致)。
**ローカルで回すエピソードはアリーナと同じゲームである。**

要点:

- **2人対戦**、10×10 の農場(5×5 の4象限、初期は NW のみ)、**30日 × 24ターン = 720ステップ**。
- 初期資金 $3,000、勝利条件はシーズン終了時の所持金。**1ターン1秒**。
- 作物 Wheat / Carrot / Tomato(継続) / Strawberry(継続) / Melon。
  2日連続の水やり忘れで雑草化(**回復不能**)。
- 家畜 Goose / Cow / Sheep。毎日 wheat を給餌、2日連続忘れで逃亡(**回復不能**)。
- 土地 NE $1,000 / SW $2,000 / SE $4,000。雇用コストは日次リセットの `fib(n)`。
- **市場**:販売価格は市場在庫に対して動的。**両プレイヤーが同じ市場を共有する**ため、
  相手の売りが自分の価格を崩す。市場注文は1ターン10件まで(超過分は黙って破棄)。
- **1.32.7 のリバランス**: carrot / tomato / egg に凸型の `hinge` 希少性ブランチが入り、
  carrot は振幅5倍。**tomato は通常のエピソードの半分でその変曲点を越える。**
  1.32.6 以前を前提にしたエージェント・解析は、この点で誤る。

## 4. 提出の契約

```python
def agent(obs):
    return {"farmer": [op, *args], "hands": [[op, *args], ...], "market": [[op, *args], ...]}
```

`tools/validate_submission.py` が契約を機械的に確認する。不正なアクションは**黙って no-op**、
例外は評価を落とす。外部ネットワーク不可、重みは archive に同梱。

## 5. ローカル評価基盤

### 5.1 エンジン

`kagsim`([destbreso/kaggriculture-cppsim](https://github.com/destbreso/kaggriculture-cppsim)、
nikital7 の bit-exact C++ 移植を 1.32.7 へパッチしたもの)を使う。

**本リポジトリでの検証結果(2026-09-03):**
- 同梱トレース 5本すべてで C++ コアが 719 ステップ完全一致(`tools/validate.cpp`)
- Python バインディングのゴールデンテスト **PASS**
- 自前エージェントでの照合: `moon198 vs starter` seed 42 →
  `kagsim` (133032.0, 3532.0) = `kaggle_environments` (133032.0, 3532.0)
- 速度: **0.36秒 対 7.0秒 = 19倍**(生の Python エージェント同士。固定アクション列なら数千倍)

`tools/engine.py` が**毎プロセスで自己検査してから使い、失敗したら `kaggle_environments`
へ落ちる。**速いシミュレータが黙って本物とずれるのは、遅いより悪い。

### 5.2 相手プール — 陳腐化する。必ず引き直す

`opponents/` は **`tools/refresh_opponents.py` が現在の公開カーネルから毎回作り直す。**
`MANIFEST.json` に取得日時・kernel ref・作者・投票数・sha256・**取得時点の作者のLBレーティング**
を記録する(作者の現在の提出に対する値であって、この凍結カーネルの値ではない点に注意)。

> **公開解は採点材料であり、解法材料ではない。**エージェントには渡さない(`docs/round1_plan.md` §5)。
> **他人のノートブックコードを取り出す処理は、必ずサンドボックス(別プロセス + 一時ディレクトリ)
> で実行する。**——この注意書きは、実際にリポジトリ直下へ他人の `main.py` を書き出す事故を
> 起こしてから書かれている。

### 5.3 何が測れて、何が測れないか(2026-09-03 実測)

| 指標 | 識別力 |
| --- | --- |
| 組み込み `starter` に対する所持金 | **ほぼ無い。**実力の異なる6体が 10% 以内に密集し、うち4体は 0.2% 以内 |
| 現在の公開プールに対する**勝率** | **この水準では効かない。**プール9体中8体に全敗・1体に全勝で量子化し、実力の全く違う個体が同じ 11.1% になる |
| 現在の公開プールに対する**マージン(所持金差)** | **有効。**moon-198 は -1,100、`r1-13-sol-low-p1` は -120,703 と明確に分離する |
| 実 LB のレーティング | 唯一の真値。ただし §1.3 の通り動き続ける |

**ローカルは「壊れていないこと」と「現在の公開フィールドに対する相対的な位置」まで測れる。**
実 LB の順位そのものは測れない。両者の対応は `docs/round1_plan.md` §4 で n=16 で較正する。
